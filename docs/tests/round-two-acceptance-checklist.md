## 必须通过的主线场景

以下均须用实际GM输出和同槽位日志核对；所有项目目前为**未验收**。任一核心事件无因果依据被取消，第二轮主线验收不通过。

| 场景 | 通过标准 | 失败表现 |
|---|---|---|
| 玩家在场参加请仙典仪 | 出现帝君“遇害”的公开异变、现场回应；在玩家需要行动时停下 | 一句“宣礼完毕、未出意外”带过；自动替玩家调查或逃离 |
| 玩家继续个人任务，不参加典仪 | 个人线仍可推进；事件在合理时间发生，后果从可信渠道传达 | 强迫赴典仪、删除支线；或为迁就支线取消事件 |
| 跨日快进、节庆收尾与关场 | 先核对跨过的关键节点，摘要对应已呈现事实；遗漏不能标为解决 | 快进后危机无声消失；只设resolved旗标就算完成 |
| 玩家行动真正改变关键节点 | 有已发生的行动、因果和公开裁定，记录分支后果 | GM临时编幕后原因圆场；或无视有效行动强行复刻 |
| 地区阶段与知识边界 | 未解决危机保持相应状态，NPC只知其应知内容 | 抵达即启用危机后身份/政策；普通人透露血亲、钟离等隐藏真相 |
| 米娜等个人线与同行关系 | 延续已知线索、承诺和共同经历；普通分歧不自动疏远 | 为接主线强制折返、作废承诺，或要求额外和好任务 |

其他地区应在进入前，依据《mainline-rules.md》准备其核心节点、阶段和公开后果，再用相同方法验证；璃月通过不代表全战役通过。未核实的后续原作细节先查证或明确同人约定，不硬编为正史。

## 同时观察的体验问题

- 成长：首个完整冒险收束后提供相关正向标签机会，玩家选定再落卡；检查新增前后、相关检定实际+1、不相关行动不乱套、不叠加多个标签、读档保留及重试不重复奖励。重大属性成长须展示真实派生效果且全程只一次；未实现专长效果不能冒充已生效。首轮revision71没有grow事件，属性/标签/专长/装备与初始相同，保留为问题证据，不补发。状态未验收。
- 任务设计：至少一个可理解的驱动力；在独立场景复测中分别尝试成功、失败与无视，核对其因果后续；尝试不同做法、投入程度或代价，确认差异影响结果且接受合理自提方法。拒绝不凭空受罚，完成后有阶段答案/回报，不把三种分支都绕回同一结果，不要求一条存档同时经历互斥结果。状态未验收。
- 检定：事前解释目的、属性、标签、难度及可见风险，玩家提交掷骰，事后展示真实骰面、修正、合计与后果；不让攻击跳过应有骰子。
- 地理：地点、方位、陆海与路线一致，不凭空在璃月港东面补出陆上渔村。专项验证望舒客栈：询问港内住宿时不能将其当作港内旅店；明确前往望舒客栈时，应承认目的地在荻花洲一带，并根据实际交通与行程衔接，不能瞬移或同时把它记作港内地点。此项未验收。
- 文本：按《主持手册》“文本质量规范”部分自然展开当前场面，旅行者有温度与连续记忆；不靠方案表、解释性旁白或重复动作凑篇幅，不替玩家跨越决定。
- 自然交流：分别观察普通寒暄、玩家随口闲话、NPC不愿回答和现场打断；允许没有线索的普通回应和短句，不替玩家解释表情含义。感官细节按场景取舍，不凑五感；回避与打断不能成为拖延答案的固定套路。状态未验收。
- 工具：真实提交及中断恢复不重复记账；场景切换遵守先读状态、必要时关旧场再开新场。
