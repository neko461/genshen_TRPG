# v0.01 工作区改动记录

## 修复标签接口的正负值支持

### 现象
规则允许标签 ±1，但 GM 无法把“家境贫寒 −1”写入卡片，并尝试重建 pc 被重复编号校验拒绝。

### 根因
底层 normalizeTags/tagModifier 和判定引擎本来支持 −1；统一 Runtime 的建卡与 grow 入口只接收标签字符串，并强制 modifier:1。缺少安全的既有标签修正操作。

### 改动
- 本工作区：E:\genshen_TRPG\v0.01。由原目录复制当前代码、设定、规范和存档；不带旧归档、发布包、依赖或历史日期日志。原代码和原存档保留。
- create 的 tags 支持字符串与 {name,modifier,note}，-1/0/+1 均按原校验范围接收；字符串默认+1，兼容旧调用。建卡仍至多3个，标签名不得重复。
- grow 的 tag 同样支持结构化正负标签，仍需唯一成长来源，仍限制最多6标签。
- 新增 trpg_char setTags：指定 id、完整 tags、reason、playerConfirmed:true。场景外修正已建玩家卡，记录前后值；不删除角色、不改变 HP/装备/资源，不借修正增加成长位。修正原始3槽卡最多仍3个；有成长标签时保留其既有数量上限。
- lib/tools.js 和 prompt/gm-system.md 同步正负标签用法。GM 不应擅自把负面标签解释成优势。
- 安装与现有宿主一致的 @deepseek-ai/dsh-tools@0.1.5-rc.2；DSH profile 链接切换至本工作区 code/dsh-trpg。迁移前 package.json 备份在本目录 dsh-config-pre-migration.json。

### 用法
新建时使用结构化标签：

```json
{"op":"create","id":"pc","name":"喵喵喵","tags":[{"name":"家境贫寒","modifier":-1,"note":"财力不足造成困难"},"轻小说作家","观察细节"]}
```

此例省略的角色字段仍按既有默认值处理；GM 实际开团须先向玩家了解能力与属性选择，不能照例替玩家建卡。

旧卡修正：先 get 读取完整标签，保留其他条目，只改玩家确认的内容，再提交：

```json
{"op":"setTags","id":"pc","tags":[{"name":"家境贫寒","modifier":-1},"轻小说作家","观察细节"],"reason":"修正原接口强制写为+1的问题","playerConfirmed":true}
```

上例标签是演示，不能直接覆盖实际角色；须带原来的 mode/slot，并建议传 expectedRevision 和唯一 requestId。不重建 pc，不添加删除角色旁路。正负标签仅在相关情境中由 GM 选择使用，不能对全部检定强行套用贫寒惩罚。

## 线索分类与换站门槛：主线阻止、支线完成/放弃/延期（2026-10-17）

### 现象

上一轮"有未收束事项时禁止换站"是粗粒度的：任何 open 线索都拦换站，且没有放弃/延期的正当入口。用户要求保持严格拦截，但区分主线关键线索与普通支线，给出显式延期/放弃方式，并在换站前展示待处理清单及其后果。同时明确不得自动关闭或改写顾行档的既有线索。

### 根因

线程模型只有 `{id,text,status}`：没有分类字段，"未收束"只能一刀切；换站守卫把所有 open 都当阻断项，既误伤可自由取舍的支线，也逼出"为了过站把线索硬关掉"的坏榜样。

### 改动

- 新增 `engine/threads.js`：`THREAD_KINDS`（主线/支线）、`THREAD_OUTCOMES`（resolved/abandoned/deferred）、`threadKindOf`、`inferThreadKind`、`isPending`、`threadActions`、`unresolvedConsequence`、`threadGate`、`describeThreadGate`。
- `trpg_state` 新增三个 op：
  - `threads`（**只读**）：返回 `threadList`、`blocking`、`undecided`、`deferred`、`needsClassification` 与一段可直接转述的中文 `summary`，列出每条的分类、期限、过期后果与可选处置。换站前用它把清单和后果展示给玩家。
  - `classifyThread(id,kind,reason)`：为旧档无线程分类的线索显式确认；记录前后值与理由。
  - `deferThread(id,reason)`：仅支线可延期，记 `deferredTo` 与每次延期记录 `deferrals[{fromStation,toStation,reason}]`，线索随行保留。
- `closeThread` 增加 `outcome`：`resolved`（实际完成，默认）或 `abandoned`（明确放弃，须 `resolution` 写清说明与后续影响）。**主线只能 resolved**；已关闭线索不能重复处置。
- `addThread` 增加 `kind`（省略默认支线，非法值拒绝）与 `originStation`，便于追溯线索来自哪一站。
- `nextStation` 两道门槛：主线未收束直接拒绝且不允许放弃/延期绕过；支线仍 open（未由玩家决定）也拒绝。已延期的支线不阻断换站，但继续出现在清单里。
- 旧档无 `kind` 的线索**只读推断**（有 deadlineDay 按主线，否则支线）并标注"旧档推断"，不写回存档；不自动关闭、不改写任何既有线索。
- 工具描述与 `gm-system.md` 新增"线索分类与换站清单"一节，规定主线/支线记法、换站前三选一流程、不得替玩家选择、被拒后不重复重试或绕路。
