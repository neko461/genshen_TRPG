# v0.02 改动记录

## 原因

既有实机对话中，玩家把行动限制为“到入口听一次，不往里走”，GM仍将其改写为进入裂口并为额外移动发起检定。现有提示词虽有玩家自主权要求，但缺少明确的工具调用前边界核对。长对话还需要一个短入口来重读该自检。

## 改动

- 在 `prompt/gm-system.md` 和 `docs/gm/gm-handbook.md` 明确玩家范围、禁止事项、条件与停止点是行动授权上限；检定、工具及NPC建议不得扩大授权。
- 在 `docs/tests/narrative-quality-regression-check.md` 增加越界动作回归场景，要求核对骰卡目的、取消是否消耗行动、未授权内容是否写入事实。
- 让 `trpg_char guidance(topic:"writing")` 返回相同短版规则；工具说明加入完整 `{op:"guidance",topic:"writing"}` JSON 示例，避免模型把自然语言签名误作入参结构。
- `dsh:check` 增加 `writing` 主题真实 Runtime 读取断言；同步产品标识和包版本到 v0.02。
- 修正快照故障注入测试：清理由初始建档生成的临时投影文件，再创建阻断目录，避免 Windows 将残留临时文件误报为目录冲突。
- 新增实机回归记录：[live-regression-v0.02-2026-10-18.md](../tests/live-regression-v0.02-2026-10-18.md)。

改前备份位于 `archive/2026-10-18-v0.02-before/`，不纳入发布内容。

## 验证与发布

本地专项测试、`dsh:check` 与 `doctor` 通过；全套 181 项测试通过。快照测试修复后定点通过；在可访问本机回环的测试环境中，3 项 HTTP 用例全部通过。DSH 完整重启后的只读 `writing` 调用成功，返回新规范且未写入存档。原有蒙德会话继续推进一轮：休整、资源、日期和安全返城按规则结算，GM未越过玩家边界，也未代替玩家接受委托。

已生成 `releases/genshen_TRPG_v0.02` 发布包，清单含文件 SHA-256；存档、归档、记忆日志、依赖目录和密钥均不进入包。发布目标为 `neko461/genshen_TRPG` 的 `main` 分支。

## 2026-10-19：主线节奏及蒙德净化设定补强

### 原因
最新长跨度对话被GM宣布为蒙德风灾收束，但没有进入风龙废墟、呈现深渊教团核心冲突或由旅行者净化特瓦林，改用外壳剥离、封锁原创运输线和七日观察替代。现有角色资料虽写了旅行者与温迪净化特瓦林，提示词却未说明旅行者曾净化受污染泪滴结晶、温迪因此请求其参与；“NPC不得万能净化”未能避免旅行者独有能力被遗漏。用户也反馈流程太慢。

- 同步主持提示词、opening主线摘要、角色与世界观资料，并在主线测试报告更正本次结局验收为未通过。无当前存档修改。

## 2026-10-19：修复读取回溯点时聊天位置丢失

### 现象
页面主动保存成功，并明确显示回溯点关联当前 DSH 聊天、消息序号 1689；读取该回溯点却只创建了游戏状态新槽，报告没有可用的 DSH 会话位置，没有创建聊天分支。

### 根因
读取面板已从回溯点列表取得并显示 `conversation`，但前端加载分支时只检查 `branch` 接口返回的 `result.conversation`。当前实测 Host 的分支响应漏返该字段，导致客户端误判为旧格式进度点。补上元数据回退后，页面又显示宿主没有自动分支接口；对照本机 DSH 0.2.0-rc.2 客户端契约发现，插件还把 `openSession` 当成工具栏组件属性读取，而该能力实际由 `uiWorkspace.openSession` 提供，且原插件未注入 `uiWorkspace`。因此分支操作一直被短路，没有调用真实 `sessions.fork`。新游戏槽仍可成功创建，原存档保持不变。

### 改动
- `code/dsh-trpg/lib/client.js`：优先使用分支响应的会话位置；响应缺字段时，回退读取已加载的所选回溯点元数据；注入 `uiWorkspace` 并用其 `openSession` 打开由 `sessions.fork` 创建的子会话。若元数据存在但宿主缺少所需接口，显示专门提示，避免误报“回溯点没有会话位置”。
- `code/dsh-trpg/test/checkpoints.test.js`：新增兼容性回归，覆盖分支响应漏返时使用列表元数据、优先采用新响应、无元数据，以及插件注入 `uiWorkspace` 并调用正式导航接口。
- 将改动同步到 `releases/genshen_TRPG_v0.02` 并刷新 Manifest。

### 验证
专项回归 4/4 通过；全套测试 179/182 通过，3 项失败均为沙箱禁止本机回环连接（`127.0.0.1` EACCES），涉及独立 HTTP 页面测试；`npm run dsh:check` 通过。刷新初版修复后的 DSH 页面并重读同一保存点，元数据已识别；当时导航接口未注入，仍未打开分支。已按宿主契约补上 `uiWorkspace` 注入与 `openSession` 调用，须再次实机复测。

### 经验
保存点列表和分支操作响应是不同接口契约；客户端不能假设分支响应会完整回显列表元数据。DSH 会话分支与页面导航是两项能力：应分别核对 `sessions.fork` 与 `uiWorkspace.openSession` 的宿主接口，并区分“没有元数据”和“缺少宿主接口”。

### 实机复测补记
刷新插件页面后，使用同一聊天回溯点再次读取：Harness 打开标题带“(2)”的新会话；读取面板确认新会话绑定到目标游戏槽 `test_newrule_auto_final_20261019`。源聊天保持不变，没有发送新的剧情消息。页面级保存→读取→自动聊天分支测试通过。
