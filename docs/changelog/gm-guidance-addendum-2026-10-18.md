# 主持规范补充（2026-10-18）

## 现象

当前实机剧情中，玩家指出更希望亲自参与并解决问题。既有规范要求自机占据重要场景、避免 NPC 包办，也要求自由输入，但没有明确说明如何平衡玩家主导与 NPC 的主动协作；实机回复还曾把局势收成数个预设行动供玩家挑选。

## 根因

“把选择交还玩家”容易被执行成行动菜单，或让 NPC 为避免抢戏而只等待指挥。缺少可操作的呈现顺序与回归样例，未能保证玩家自己提出办法并实际影响问题结果。

## 改动

- code/dsh-trpg/prompt/gm-system.md：明确玩家决定解决目标、办法与风险；GM先呈现事实、阻碍、资源和可见后果，不列预设行动菜单，不以重复观察/汇报拖延；NPC按能力与职责协作，不能包办或摆设化；玩家提出足够的方法后不临时加门槛。
- docs/gm/gm-handbook.md：在玩家角色叙事占比下增加“玩家主导解决问题”，列出规则解释和验收点。
- docs/tests/narrative-quality-regression-check.md：增加玩家提出解决目标、NPC有实际行动、GM接受自由方案的回归场景。运行时已把关键场景自检段作为 guidance writing 返回内容，因此同一段自检的修改会自动包含此项，不需改运行时代码。
- MEMORY.md、docs/README.md：同步长期偏好和补充记录入口。
- 改前副本：archive/2026-10-18-player-agency-guidance-before/。已发布的 releases/genshen_TRPG_v0.02 未修改；本次为后续工作区修订，尚未打包或发布。

## 验证

写后回读并比对各处规则。node --test test/mainline.test.js（3/3）、npm run dsh:check（19工具注册、存档路由只读枚举、writing指引及参数检查）、git diff --check 均通过；新增测试断言确认writing指引包含玩家主导、NPC协作和不使用预设行动菜单。检查验证规则文本和读取接口，不等于证明模型每次都能遵循；仍需用回归场景实机评分。

## 经验

“把选择交回玩家”不等于列出选择菜单。GM 应让玩家自己构思和执行解法，同时让 NPC 依据专长、目标与处境承担真实协作。
