# 同伴与高阶角色战斗介入机制

版本：v1.0（规则设计稿，2026-10-18）
定位：合并“招募角色即兴生成战斗能力”与“七神及顶级战力剧情介入”两份提案。世界观、人物时序以核心圣经和时间轴为准；本文件不覆盖《finalized-stat-rules-v1.0.md》的骰子、伤害、敌人缩放和存档规则。

## 一、先区分两种参与方式

**正式战斗同伴**是经玩家提出并由角色本人明确答应加入队伍的普通角色。确认加入后，默认持续随队并作为常规同行成员；进入战斗时，若同伴与队伍在同一现场且没有已成立的缺席原因，就按同行队员处理，不必每场重问是否愿意协作。玩家可以提出离队，角色也可以基于已建立的人物立场主动离开；临时分头行动、受伤休整或剧情职责造成的缺席，须有具体事实并及时说明。角色的职责会影响其行动方式，不会自动取消已成立的队伍关系。

一次性协助、关系良好或仅在某个任务同行，不自动等于正式战斗同伴。若双方只约定了某段行程或单次任务，约定结束后按当时谈妥的期限处理；要建立持续队伍关系，应在剧情中明确加入并记录。关系与招募状态不可混为一谈。

**高阶角色介入**是七神、古龙大权持有者或其他符合当前剧情力量尺度的关键人物，在单一危机节点采取一次有边界的行动。他们不是可招募同伴，不获得常规战斗回合、常驻角色卡或玩家操控权。示例名单不是封闭名单，也不代表所有被提及者在每个战役时点都可接触或属于同一力量等级。

出场前统一核对四项：人物是否在场或有可信抵达方式；当前时序是否允许；人物为何愿意或必须介入；介入会具体改变什么。只听说、祈祷、持有信物或关系很好，不会自动把人物召来。缺少依据时先通过正常剧情建立联络，不凭空安排救场。

## 二、临时战斗同伴的生成公式

生成次序为：**确认是否正式加入及其职责 → 确认元素和武器 → 分配标准属性 → 选一个核心机制 → 写清战术习惯与边界 → 核对工具是否能结算。**这是主持后台的建卡流程，不向玩家一次性抛出机制菜单。每场战斗最多一名新招募的 NPC 占据独立同伴战斗位；已在队伍中的正式同伴不算“新招募”，但启用其战斗位时仍须把该角色计入战斗人数并重新验证敌人缩放，不能增加免费回合而沿用旧缩放。正式加入须由角色本人明确同意；持续关系不需每场重复征求同意，单次任务协助也不会被擅自升级为正式加入。

### 1. 元素只提供战术倾向

元素用于帮助塑造招式与配合，不强制角色只能担任一种职业，也不自动附赠伤害、状态、反应或控制：

| 元素 | 常见战术倾向 |
|---|---|
| 风 | 聚集、位移、扩散 |
| 岩 | 防护、稳固阵线、破坏障碍 |
| 雷 | 高频攻击、快速附着、能量配合 |
| 草 | 持续影响、激化配合、召唤物 |
| 水 | 治疗、限制行动、高频附着 |
| 火 | 爆发、破坏障碍、融化配合 |
| 冰 | 限制行动、冻结配合、暴击倾向 |

元素反应必须符合《finalized-stat-rules-v1.0.md》并由现有战斗结算处理。角色没有神之眼或其他已确认来源时，不得仅凭武器或元素定位赋予其元素能力。

### 2. 武器决定战斗手感，不给通用检定加值

沿用数值定稿中的五类武器及其伤害、减伤、先攻、仇恨和专属效果：单手剑偏均衡，双手剑偏重击，长枪偏距离与稳阵，弓偏远程和弱点，法器偏元素攻击。武器不提供通用检定修正；“判定+1/-1”不作为本系统规则。武器数值须由角色卡和引擎的武器表取得，不由 GM 临时估算。

属性采用角色卡同一预算：`+2/+1/+1/0/0/−1`，六项对应体魄、灵巧、心智、感知、交涉、意志。把 +2 放在该人物最擅长的实际战斗行动属性，两个 +1 分配给次要长处与生存能力，−1 放在符合人物设定的弱项；不得由元素或职业标签直接推出性格与属性。基础 HP 按现有公式 `120 + 体魄×15`，减伤及武器数据沿用现有推导，初始元素能量按角色规则。招募者提供的武器或装备必须先在剧情中成立。此为目标建卡公式，当前工具没有任意 NPC 建卡/招募接口，不能据此手写存档。

### 3. 只选一个核心机制

每名临时同伴只设一个核心战斗机制，避免把元素、武器和角色天赋叠成一套无成本全能技能：

| 模板 | 设计用途 | 必须说明的边界 |
|---|---|---|
| 战术辅助型 | 为一名队友提供一次明确的防护、治疗或行动协助 | 目标、次数、资源成本与实际恢复/防护量；不能把“协助”同时算作攻击和加值 |
| 持续输出型 | 对一个目标或有限区域施加持续元素压力 | 持续轮数、每轮结算时点、目标上限、是否可被打断；不得每轮重复叠加同一效果 |
| 单体爆发型 | 准备后集中打击一个目标 | 准备条件、消耗、目标、结算伤害；准备被打断时的结果 |
| 聚怪控场型 | 改变有限范围内敌人的位置或短暂限制行动 | 范围、持续时间、首领抗性和失败边界；不能默认全场控制或跳过敌方所有行动 |

每个核心机制限一个主要效果：辅助不同时治疗、加骰并上盾；持续伤害不得同时聚怪；爆发只作用于一个目标；控制不附赠高额伤害。数值边界沿用工具已有的伤害、属性、反应、减伤和元素能量规则，不发明额外骰子或永久加值。核心机制不自动拥有“元素爆发”资源。只有角色卡、资源成本和触发条件已明确记录，且工具能结算时，才能按数值能力使用；否则只作为待实现的设计提案，不在正式战斗中宣称已造成数值效果。

### 4. 同伴由 GM 执行，玩家建议不等于接管

同伴按已建立的性格、职责、现场危险和关系行动。玩家可给出战术建议，同伴会认真考虑，但仍可依性格和当下判断调整或拒绝；GM 不把建议改写成玩家角色的动作，也不替玩家宣告同伴已同意。

角色行为应具体而有差异：安柏会优先注意平民与远程掩护；凯亚会判断最大威胁并寻找控制机会；迪希雅倾向保护前线，但会衡量风险。例子是倾向，不是固定脚本。元素配合须看当前附着、行动顺序与资源；不得为了展示反应让同伴无视正在发生的危险。

强力技能或“大招”不每场自动释放。仅当角色确有该能力、资源满足、且当前危机足以让其承担消耗时考虑使用；使用前公开玩家能理解的重大风险或代价。角色 HP 归零时按重伤退场处理，不死亡、不再行动；治疗、救回或重新参战须有已实现的能力和明确结算，不能一句旁白清除重伤。

## 三、七神与顶级战力的剧情介入

高阶人物的力量不是常驻队伍的免费解法。其介入须服务于已经发生的危机，并给玩家留下可改变局势的行动。人物可以负责挡住一波攻势、打开一条有限通路、压制一个威胁窗口，或协助撤离；不能因其出场就自动解决整项委托、整场首领战或地区主线。

每次介入在主持后台先写清：**触发依据、人物在场/抵达理由、介入目标、效果范围与持续时间、敌方或环境仍可采取的反制、玩家接手的具体行动、可预见后果。**介入前若玩家能够影响是否接受、保护谁或把握哪个机会，应把选择留给玩家；不要先演完决定性技能再询问玩家意见。介入不得替玩家选择目标或替玩家说话；若玩家没有主动呼唤，人物也可因已成立的职责、承诺或危机自主行动，但须通过场景给出可理解的原因，不把“自主介入”写成玩家已召唤或欠下人情。

一场首领战或同一连续危机中，最多由一名高阶人物完成一次决定性介入；这条限制用于防止救场轮番叠加，不代表每章只能出现一次重要人物，也不阻止他们在别的场景以普通身份交谈或提供非战斗帮助。完成介入后退出战斗焦点，把局势与下一步交还玩家。首领可被短暂牵制或被迫改变阶段，但不能被默认秒杀、永久石化、无视所有防御或剥夺行动权。介入不自动改变玩家队伍人数、敌人缩放或敌人 HP；若介入确实改变敌方状态，须由已实现的效果工具结算，否则只能描述不涉及数值的场景变化，不把叙事描写冒充状态效果。

同一场战斗不可同时叠加“NPC 独立战斗同伴”“一次性 NPC 支援”和“高阶人物战斗介入”三种额外 NPC 战斗影响。选择普通同伴时按其回合与人数缩放；选择支援或高阶介入时不增加独立攻击回合。高阶人物可在其他场景以不结算数值的方式出现或协助。

代价必须来自当前人物、地点和事件中已经成立的因果，并在玩家作出相关选择前说明。疲劳、职责冲突、公开身份、资源损耗或地区后果都只能在有设定和现场依据时采用；神力出手不自动导致地脉震荡、数日降雨、天理注视或其他固定灾害。玩家不因 NPC 自主救援而被强制扣除自己的物品、HP、关系或奖励。

### 人物和设定校准

“七神”“龙王/古龙大权”“其他顶级战士”是不同身份与力量来源，不能合并成同一类规则。那维莱特属于水龙王而非尘世七执政；人物是否担任地区职务、是否离开驻地、当前力量状态以及能否使用特定招式，按对应时间线与人物资料核实。钟离交出神之心、雷电将军相关神之心经历，不足以推出统一的“力量大幅减弱”规则；也不预设动用神力必然招致天理注视。

例如：温迪的风可以在有限战场创造聚拢或扩散机会，不写成全图吸敌；钟离可以为撤离或队伍行动争取一个明确窗口，不默认全体敌人石化三轮；雷电将军的强力一击可以成为一次有条件的剧情攻势，不把非魔神敌人写成必杀；那维莱特可依据当前剧情与职责选择是否亲自行动，不获得“裁定敌人行为”的通用规则；玛薇卡的鼓舞或攻击应限定目标与持续时间，不向全队永久加成。以上均为设计示例，具体能力以战役时序、角色资料和实际实现为准。

## 四、v0.01 的实际执行边界

本节是目标规则；当前代码尚未实现通用 NPC 战斗角色卡、NPC 独立行动顺序、AI 同伴回合、NPC HP/重伤结算、任意核心机制或高阶剧情技能结算。不能通过文档把这些功能说成已经接入。

目前 `trpg_party support` 不再限定安柏、凯亚、丽莎、迪卢克：任何已在剧情中出现、并与行动者建立“信任”或“羁绊”关系的 NPC 都可被选为一次性支援；GM须说明其此刻在场、愿意协作且具备相应能力的剧情依据。每场景仍限登记一名 NPC，战斗中一次为当前行动者提供 +1 处境修正。接口不负责登记正式队员或持久化队伍名单，也不会自动核验 NPC 身份、在场或意愿；这里描述的是工具校验边界，不表示正式同伴每场都要重新请求意愿。正式加入并记录的同伴默认按队伍关系协作；GM仍须依场景事实判断其是否在场，不能把缺席角色计入支援。该接口不提供 NPC 独立攻击、治疗、护盾或控制。未达到信任关系、尚未在剧情中出现或没有合理协作依据的 NPC，不能仅凭工具调用临时加入。其他 NPC 仍可按已有事实提供叙事和非战斗帮助，但不能伪造数值战果。

当前引擎尚无正式 NPC 招募、离队、持续队伍名单或通用 NPC 战斗位的落档接口。因此，上述“正式同伴默认随队”的规则是目标行为，不能靠 `support` 假装已登记或产生独立战斗数值；在引擎支持前，GM须说明这一执行边界，并把双方明确约定留在可追溯的剧情记录中，不得每场把已经同意的角色说成尚未答应。

在通用同伴行动与高阶技能解析器实现前，GM 只能使用已有角色卡、已有支援接口和已支持的战斗动作。无法由工具表达的提案先记录为待实现能力，不在真实存档中创建虚构的 HP、行动、次数、状态或伤害；遇到会改变当前战斗胜负的缺口时，暂停该结算并向玩家说明。后续实现至少须覆盖：招募/离队与在场记录、同伴属性和装备来源、战斗名单与敌人缩放、AI 行动、伤害/治疗/状态、重伤恢复、介入次数/代价、Journal 回放与旧档兼容，并为每条路径补回归测试。
