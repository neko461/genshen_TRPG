# 群攻与单体攻击核算 v0.5

> 承接 `数值结算v0.4-缩放与恢复.md`。本轮核算你提出的**两种攻击类型**：
> ① 群攻（AoE）：`攻击力 × (1 − 0.10 × n)`
> ② 随机单体攻击：`攻击力 × (1 + 0.10 × n)`
>
> **核算结论：这两种修正的净效果互相抵消，幸存轮数恒定。要真正实现「人多压力大」，需要换一个杠杆。**

---

## 第一部分：先建立核算模型

### 1.1 两种攻击的每名玩家实际承受

设首领每轮攻击 **2 次**，群攻与单体各占一半（1 次群攻 + 1 次单体）。

| 攻击类型 | 每名玩家承受的伤害 |
|---|---|
| **群攻（AoE）** | `A₀ × (1 − 0.10n)`　← **每个玩家都吃满** |
| **随机单体** | `S₀ × (1 + 0.10n) / n`　← **只有 1/n 概率落到你头上** |

**合计每名玩家每轮承受**：

```
D(n) = A₀ × (1 − 0.10n)  +  S₀ × (1 + 0.10n) / n
       └─ 群攻项：不除 n ─┘  └── 单体项：要除 n ──┘
```

**这是核算的关键**——群攻与单体的**分摊方式不同**：群攻必中所有人，单体只中一个。所以两者的 n 修正在**算术上不可能互相抵消**，而是产生一个**偏向群攻的净结果**。

### 1.2 无修正的基线（n 修正全去掉）

```
D(n) = A₀ + S₀/n
K(n) = H₀n / (D_per_player)          ← 击杀轮数（队伍总输出 = D_per_player × n）
T(n) = H / D(n)                      ← 幸存轮数
```

| n | D(n) = A₀ + S₀/n | K(n)（击杀轮数） | T(n)（幸存轮数） |
|---|---|---|---|
| 1 | A₀ + S₀ | H₀ | H/(A₀+S₀) |
| 2 | A₀ + S₀/2 | 2H₀ | H/(A₀+S₀/2) |
| 3 | A₀ + S₀/3 | 3H₀ | H/(A₀+S₀/3) |
| 4 | A₀ + S₀/4 | 4H₀ | H/(A₀+S₀/4) |

**注意两件事**：
1. **单体项的 1/n 本身就让人多的压力变小**（人越多，某一击落到你头上的概率越低）——这是「人多的天然优势」。
2. **击杀轮数 K(n) = nH₀，随 n 线性增长**——这是错的，说明**首领 HP 若固定不变，队伍越大越快打完**。你 v0.4 的「HP × n」正是为了修掉这一点 ✅ 所以**「血量 × n」是必要且正确的**（我上一轮对它的质疑作废，见 §4）。

## 第二部分：加入你的 n 修正后

### 2.1 每名玩家承受（A₀ = 24，S₀ = 26）

```
D(n) = 24 × (1 − 0.10n) + 26 × (1 + 0.10n) / n
```

| n | 群攻项 24(1−0.1n) | 单体项 26(1+0.1n)/n | **D(n) 合计** | 相对 n=1 |
|---|---|---|---|---|
| 1 | 21.6 | 28.6 | **50.2** | 基准 |
| 2 | 19.2 | 15.6 | **34.8** | **−31%** |
| 3 | 16.8 | 11.4 | **28.2** | **−44%** |
| 4 | 14.4 | 9.1 | **23.5** | **−53%** |

**结论：每名玩家承受的伤害随人数增加而大幅下降**，n=4 时只有 n=1 的 **47%**。

**即：你的两个修正的净效果与预期相反**——它们**降低**了多人的压力，而不是增加。

### 2.2 为什么会这样（关键的机制原因）

| 项 | 随 n 的变化 | 为什么 |
|---|---|---|
| 群攻项 | `× (1 − 0.1n)` | 你给群攻加了随人数**递减**的修正，于是人越多、每人吃的群攻越少 |
| 单体项 | `÷ n` 再 `× (1 + 0.1n)` | `(1+0.1n)/n` 在 n=1 时是 1.1，n=4 时是 0.35——**你在做除法，而分母是 n**，所以它天然暴跌 |

**也就是说**：
- **群攻**本该是「多人压力」的来源（因为它一次打所有人）——但你给它加了**递减**修正；
- **单体**本该是「人数越多越分散」——你给它加了**递增**修正，但那个 `(1+0.1n)` 的增长远远追不上 `1/n` 的衰减。

**两个修正在数值上都太小（±10% 级别），而 `1/n` 是 −75% 级别**，所以总趋势完全被除法主导。

### 2.3 验证：幸存轮数不恒定

设玩家 HP = 120，首领 HP = 90n（你 v0.4 的「HP × n」）：

| n | 首领 HP | 队总输出 | 击杀轮数 K | D(n) | **幸存轮数 T** | K vs T |
|---|---|---|---|---|---|---|
| 1 | 90 | 25 | 3.6 | 50.2 | **2.4** | ❌ 打不完 |
| 2 | 180 | 50 | 3.6 | 34.8 | **3.4** | ⚠️ 勉强 |
| 3 | 270 | 75 | 3.6 | 28.2 | **4.3** | ✅ |
| 4 | 360 | 100 | 3.6 | 23.5 | **5.1** | ✅ 偏轻松 |

**K 恒定 3.6 轮 ✅**（你的「HP × n」把它修好了），**但 T 从 2.4 涨到 5.1**——**人越多越轻松**，与你要的「增加多人压力」相反。

## 第三部分：要让「人多压力大」，正确的杠杆是什么

### 3.1 原理

要让人多更有压力，**必须让随 n 增长的那一项，是「不打折、不除 n」的那一项**。

**只有群攻满足「不打折不除 n」**（它一次打所有人，每人吃满）。

所以：**群攻必须随 n 递增**，而不是递减。

### 3.2 修正后的公式

把两个修正的**方向对调**：

```
群攻（AoE）    ：A₀ × (1 + 0.10 × n)     ← 递增（人越多，每人都挨得更重）
随机单体        ：S₀ × (1 − 0.10 × n)     ← 递减（人越多，单点越轻，因为容易被分摊/救援）
```

**核算**（A₀ = 24，S₀ = 26）：

```
D(n) = 24 × (1 + 0.10n) + 26 × (1 − 0.10n) / n
```

| n | 群攻项 | 单体项 | **D(n)** |
|---|---|---|---|
| 1 | 26.4 | 23.4 | **49.8** |
| 2 | 28.8 | 10.4 | **39.2** |
| 3 | 31.2 | 6.2 | **37.4** |
| 4 | 33.6 | 3.9 | **37.5** |

| n | D(n) | 幸存轮数 T（HP 120） |
|---|---|---|
| 1 | 49.8 | 2.4 |
| 2 | 39.2 | 3.1 |
| 3 | 37.4 | 3.2 |
| 4 | 37.5 | **3.2** |

**n ≥ 2 时基本恒定在 3.1–3.2 轮** ✅ —— 这就是你要的「人多的压力维持在合理水平」。

**但 n=1 时只有 2.4 轮**（比 4 人更危险）——这需要单独用「单人档数值」处理（你已裁定分两套数值，正好由 A 套承担）。

### 3.3 更进一步的选项：群攻伤害随 n 线性增长

若你觉得「3.2 轮恒定」还不够体现「人多更难」，可以让**群攻伤害直接乘 n**（而不是 `1+0.1n`）：

```
群攻：A₀ × n
```

| n | 群攻项 A₀×n | D(n) | 幸存轮数 |
|---|---|---|---|
| 1 | 24 | 49.4 | 2.4 |
| 2 | 48 | 55.4 | **2.2** |
| 3 | 72 | 76.5 | **1.6** |
| 4 | 96 | 98.2 | **1.2** |

**这会导致 4 人一轮就倒**——明显过头。**不可取。**

**结论**：`1 + 0.10n` 的递增幅度**正好合适**——它足够让压力不衰减，又不会失控。**你的 ±10% 思路是对的，只是两个方向需要对调。**

## 第四部分：更正我上一轮对「血量 × n」的质疑

**上一轮我说**「血量 × n 只是在抵消玩家人数优势，没有缩放难度」——**这个判断错了**。

**它是必要的**：若无此缩放，击杀轮数 K = nH₀ 会随 n 线性增长，4 人队 1 轮就打死首领。**「血量 × n」把 K 拉回了恒定值** ✅。

**所以维持你的原式**：

```
首领 HP       = H₀ × n            ✅ 保留
首领 群攻     = A₀ × (1 + 0.10n)  ← 方向对调（原为 −）
首领 单体     = S₀ × (1 − 0.10n)  ← 方向对调（原为 +）
首领 每轮攻击次数 = 2（1 群攻 + 1 单体）
```

**我上一轮推荐的 ×n^1.5 也随之作废**——因为有了群攻项承担「人多压力」，HP 不需要超线性增长。

## 第六部分：单人档（A 套）的独立处理

单人模式是 **玩家 + 旅行者 = 2 个行动位**，但**队伍人数 n 记为 1**（旅行者按 0.8 折算）。

这会使 n=1 的公式给出的压力（T = 2.4 轮）**过重**。因此**单人档需要下调基础值**：

| 项 | 单人档（A 套） | 多人档（B 套） |
|---|---|---|
| 首领 HP | **70 × n** | 90 × n |
| 首领 群攻 | **18** × (1+0.1n) | 24 × (1+0.1n) |
| 首领 单体 | **20** × (1−0.1n) | 26 × (1−0.1n) |

**核对单人档**（n=1，玩家 HP 120 + 旅行者 96）：

| 项 | 值 |
|---|---|
| 首领 HP | 70 |
| 群攻 | 18（打两人各 18） |
| 单体 | 20（随机打一人） |
| 玩家每轮承受 | 18 + 20/2 = **28** |
| 玩家幸存轮数 | 120/28 = **4.3 轮** ✅ |
| 队伍总输出 | 25 + 20 = 45/轮 |
| 击杀轮数 | 70/45 = **1.6 轮** ✅ |

**击杀 1.6 轮、幸存 4.3 轮**——**偏轻松**。若要让单人首领战更紧张，把首领 HP 提到 **110**（击杀 2.4 轮），幸存仍有 4.3 轮 ✅ 推荐用 110。
