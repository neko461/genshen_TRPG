# v0.01 运行架构

## 单一操作入口

试玩 UI → 本机 HTTP → Runtime；DSH → defineTool → 同一个 Runtime；CLI → 同一个 Runtime。没有第三套前端假结算。原始引擎纯函数仍可独立测试。

## 单一事实源

调用显式带 mode/slot。Runtime 校验输入并在 Journal.commit 中修改克隆状态。事件 fsync 是提交点，包含编号、时间、操作、输入、骰面与结果、完整 after 状态、前一条校验值、请求编号；state.json 只是投影。提交之后即使写投影失败，也返回成功和警告，下一次从日志恢复。

并发通过每槽位排他锁拒绝；expectedRevision 拒绝陈旧操作；requestId 重试不重复产生随机结果或资源变化。旧请求重试返回原动作结果与最新状态，避免页面倒退。日志错误停机，不静默略过。新建检测旧档，不覆盖或混合新旧数据。

## 行动与资源

战斗由先攻游标决定当前单位。一次动作查卡、查装备、掷骰、扣资源、扣血/附着/状态，作为同一事件提交。全员行动后才能轮末结算；首领按血量切阶段，不凭空加 HP，四轮超时结束。召唤、核心、护甲、锚点与蓄力用统一互动模板，不再独立复制一群完整敌人。

库存中装备逐件唯一编号，消耗品可堆叠；穿戴与强化都消费真实库存。派生值从基础卡、武器、圣遗物与套效计算，随后同步旅行者；提高上限不直接补当前值。料理/药剂计数在同一场景共享，空场景不恢复，神像与关场短休不叠加。

## 剧情与信息

场景保留目标、参与者、检定、消耗品次数、实际进展、是否战斗与恢复标记。关系按玩家记录、关键事件单步升级；背叛暂停支援。时间轴包含回蒙德插入段，不能直接跳站或用多元素绕过共鸣解锁。

lore 仅返回 data/lore.json 人工审核内容：阶段满足且公开，或剧情级已取得对应解锁旗标。禁止请求隐藏/禁止上限和任意文件路径，不把 GM 文件读进玩家接口。索引覆盖不足时返回暂无已解锁资料，不由模型硬编正史。

## 首测入口与边界

HTTP 仅监听 127.0.0.1；限制 Host/Origin/Content-Type、64 KB 正文和每次服务随机令牌。网页只显示文本，不把玩家姓名、反馈或工具文本当 HTML。无远程模型或数据上传。

本轮验收聚焦持久化机制和固定场景。真实 DSH 宿主、敌人完整反应链、自动专长、大规模增量日志与完整自由叙事不宣称完成。第一轮测试指南明确这些边界。
