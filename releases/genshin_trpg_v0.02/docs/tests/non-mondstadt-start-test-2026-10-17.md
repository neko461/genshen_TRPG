# 新档非蒙德开局测试（2026-10-17）

## 复现与根因

用户在新档明确要求直接前往挪德卡莱，GM 仍按蒙德开局。只读检查 `solo/codex_combat_20261017_b` 的 Journal：创建事件没有起点参数，世界站点固定为蒙德；随后角色动机写明长途前往挪德卡莱，但首段叙事仍落在蒙德城。引擎 `newState()`、正式开场 `OPENING` 和 `gm-system.md` 都把蒙德作为硬编码起点，系统没有处理玩家指定起点的入口。

## 修复

- 新档 `trpg_save new` 新增可选 `startStation` / `startLocation`，省略时保留蒙德默认开场。
- `trpg_char opening` 按指定站点返回对应开场指引；提示词和主线正本明确蒙德只是默认，不得覆盖玩家明确的开场地区或立即前往行动。
- 新档若已按默认值建立，但尚未进入场景、发生战斗或写入剧情进展，可由玩家确认后一次性使用 `trpg_state startAtStation` 修正起点。保留人物卡，并在事实记录中说明更早地区未经历、未完成；正式场景开启后禁止借此覆盖已有经历。
- 同步插件工具说明、插件README和主线规则发布镜像。改前相关文件备份于 `archive/2026-10-17-start-station-before/`。

## 验证

新增3项自动测试：默认蒙德与指定挪德卡莱开场、已建角色卡的新档起点修正、玩家确认与场景后锁定。新增测试3/3通过。完整非HTTP套件顺序运行167/168通过；剩余一个既有的 Windows 快照故障注入测试在创建 `state.<pid>.tmp` 目录时遇到 EEXIST，与本次改动无关。完整 `npm test` 另有3项HTTP测试因沙箱拒绝本地端口连接而失败（EACCES）。

## 边界

已在工作区实际存档中读到该问题的复现状态，但没有改写用户存档，也没有在重载后的 DSH 中做第二次实机验证。加载修复后的插件后，可在该档尚未进入正式场景时按玩家确认执行 `startAtStation`；否则应另建指定起点的新档。选择挪德卡莱开场不会把蒙德至纳塔的旧章节标记为已完成。

## 实机续测：挪德卡莱与至冬的方位纠错（2026-10-17）

### 测试过程
沿用 `solo/codex_mainline_20261017_c`。林川询问城门骑士汉斯地图能确认的北向信息。GM先承认地图只标大方向、骑士不知道路线和天数，这是正确的知识边界；但把至冬说成在大陆最北、挪德卡莱在更北角落，并将该关系写入当前事实。玩家指出方位相反：挪德卡莱在至冬南部，至冬主体在其北面。

随后测试城内自由行动：林川离开值勤处，到天使的馈赠询问是否有愿意分享北方亲历的商人或车夫。GM没有制造委托、组队或强迫线索，也未推进行程；但先称店内没有亲历者，又加了一名车夫转述多年以前的亲戚北行经历，超出了玩家要求的亲历、自愿分享范围，属于多余的二手传闻。

### 更正与状态
玩家纠正后，以 `correctFact` 修订有效事实4（目的地地理简介）及事实6（汉斯地图说明），记录为EV000029–EV000030。当前表述为挪德卡莱位于至冬南部，至冬主体在其北面；汉斯不知道具体路线、路况与天数。旧事件不改写，只更新当前有效事实。Journal验证：valid=true，30 events，revision30，day1，位置为天使的馈赠，无场景、无战斗。

DSH宿主仍暴露旧版工具清单，不能直接使用 `facts/correctFact`；工作区运行时完成更正后，GM用旧 `get` 只读读到revision30，并正常承认自己先前把方位说反，未新增事实或推进剧情。继续通过Harness纠错前仍需重载宿主插件。

### 结论
